Use case: ui-mockup.
Create ONE polished, high-resolution UI DESIGN CONTACT SHEET with SIX meaningfully different desktop generation-progress layouts for Learning Studio, arranged exactly THREE COLUMNS by TWO ROWS. All six cells must have comparable scale and the same running state, project, copy and dark theme. Each cell is a complete miniature desktop app window with the same slim icon rail, compact project sidebar and large primary workspace. Outside each window place a large clear option number and short caption: "1  Centered dialog", "2  Right panel", "3  Main workspace", "4  Bottom panel", "5  Inline topic", "6  Split preview". Neutral charcoal sheet gutters. Aim for a large landscape canvas and crisp legible type, not a photograph or tilted device mockup.

INPUT IMAGE 1 is a style reference only: reproduce its restrained dark app palette, neutral system sans typography, narrow outer icon rail, sidebar, spacious document surface, rounded panels, and small muted purple activity accents. INPUT IMAGE 2 is an outline structure reference only: adapt its reading surface, numbered topic rows and document hierarchy to that dark styling. No personal/account details from reference images; bottom account label only "Account". Preserve the familiar app shell, but use "Bayesian reasoning" as the project in all cells.

COMMON STATE: An existing topic is being rewritten to add historical context, using streamed structured draft content. The user can NOT start any other AI request until this one finishes or is cancelled. AI edit controls and AI-submit controls are gray/disabled. Navigation and saved-content reading may remain available in panel layouts; gray out only the affected document/actions, keeping inactive text legible. The saved outline remains intact. Progress is indeterminate: no percent completion, no invented ETA. Draft must be clearly labeled "Draft preview · Not saved". Keep the active generation surface bright enough to read while the underlying saved document is visibly muted. Make each generation surface substantially more prominent than a small status banner. Always show an explicit "Cancel" button on the active surface, not a confusing close-only icon. No developer logs, raw JSON, terminal display or private thinking.
