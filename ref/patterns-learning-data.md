# Learning and data patterns

## Illustrated chapter and provider ownership

[ADR-0026](ADRs/ADR-0026-illustrated-topic-content-and-openrouter-media.md) implements independent versioned `.edu/chapters` manifests, `.edu/content-runs` checkpoints and immutable topic-owned `content/<chapter>/<revision>` output through the chapter runtime and named bridge. Sectioned provider/Appearance Settings and the offline reader/generation controls are implemented; individual image replacement UI remains pending. Preserve `.edu/project.json`, sources and unrelated topics. Main binds portable project/topic identity, exclusive folder ownership, topic/context/source digests and independent manifest commit marker. Exact saved objectives map to stable sections via zero-based indices; incomplete text is checkpoint progress, while complete prose may be `text-only` or `needs-images`. Image filenames bind stable image/version identity. Replacements retain unchanged assets through known prior revision pointers; pointer bounds never authorize deleting history. Candidate revisions bind the expected current manifest/image version and publish only after explicit acceptance. Save retry performs no inference; unresolved dispatched image slots cannot replay through ordinary Continue.

Complete prose/checkpoints must fit every legal one-to-four-section reader cursor window, including repeated plan/image/source metadata. Reserve bounded future asset metadata before paid illustration dispatch; do not increase the 2 MiB reader frame or truncate a chapter to make it readable. Snapshot image-slot settings retain recorded quote context, while published run identity binds historical save-retry presentation to the actual accepted run. An acknowledged slot retry generates only that selected image; untouched planned slots remain for explicit Continue. These projections change no portable schema version or source ownership.

`src/main/storage/topic-content-repository.ts` resolves private authority through `WorkspaceService` without saving project metadata or accessing an account. Explicit writes and recovery cleanup enter the existing serial mutation queue; ordinary reads only inspect recovery. Private source evidence contains the digest of the exact bytes delivered to inference and accumulates monotonically. Changed earlier evidence cannot be adopted by a later read. Publication rechecks that evidence and the independent manifest baseline immediately before replacing the marker. It rejects all current/retained revision IDs and preserves every retained pointer. Immutable files use private durable temporary ownership and a no-clobber publication step; serialized recovery may finish only a proven owned temporary link. Unknown files, journals and links remain conflicts and deny generation before inference. Main checks raster containers/digests; sanctioned utilities fully decode off main and main serves authorized opaque raster identities.

Published/current/prior revisions are retired from resumable progress. An exact `pendingResultId` binds in-session validated checkpoint/asset recovery or a proven publication journal; Retry Save never repeats inference. Completing illustrations preserves the published source/context fingerprints and changes only the expected manifest marker, rejecting stale prose before image dispatch. Failed/requested/unresolved slots require exact explicit uncertain-charge acknowledgement; `previousAttempts` retains append-only call lineage.

Explicit discard removes only proven owned control state and preserves immutable output. Before deleting a durable checkpoint, main archives its bounded immutable ownership provenance in `.edu/content-abandoned`, keyed by run and checkpoint revision. These records are never resumable progress. Published, pending and abandoned generated namespaces are excluded before source quotas; ordinary manual content remains eligible. A failure after confirmed chapter publication to update profile-ledger disposition reports an accounting issue while keeping the chapter saved/readable and its independently recorded cost intact.

OpenRouter keys, fixed image preference, cached capabilities and ledger are profile-owned and independent of ChatGPT, exposed through named authorized runtime IPC. Key validation precedes replacement; protection/fallback reporting follows ADR-0014 without secret readback. Configuration mutations exclude provider lease acquisition across durable writes. Cache records bind the connection epoch; stale refreshes cannot restore a removed connection. Every app request requires a durable intent before dispatch and independently retained outcome/cost transitions. Known exact decimal USD and unknown costs remain distinct from publication status; latest cost counts once per call, and provider-wide key usage is separately labelled. Intents reserve space for terminal billing and bounded history pages; corrupt history blocks paid dispatch and preserves existing bytes. Price lines preserve billable unit/variant/compatible settings; incomplete pricing or unproven variants produce unknown estimates. Cached quotes and paid authorization share endpoint compatibility and routing. No prompt/raw payload/full URL enters the ledger. Metadata and key changes do not automatically run paid inference. See ADR-0026 for cache, liveness, byte/pixel and recovery bounds.

An explicit illustrated activation may refresh missing or stale capabilities under its provider lease. It pins prior compatible settings, releases ownership on discovery failure and leaves valid prose available. Ordinary reading, cached quotes and deliberate text-only generation never refresh metadata; a cold cache therefore does not create background requests.

Governed by [ADR-0008](ADRs/ADR-0008-chatgpt-plan-connection-and-pi-foundation.md) and [ADR-0009](ADRs/ADR-0009-portable-project-workspace.md). ADR-0003 records the retired demo baseline.

## Project ownership

`src/core/workspace/service.ts` owns project use cases behind async storage/registry ports. Main canonicalizes native-selected folders, reads bounded metadata, and performs atomic saves. Opening creates no `.edu` and makes no inference request. Explicit model or brief changes create portable identity on first save.

`src/shared/workspace.ts` defines versioned `.edu/project.json`: identity, revision, display name, timestamps, model, brief, and optional saved outline. `src/shared/outline.ts` validates lessons, objectives, module methods/tasks, assumptions, additions, and coverage independently of origin. Model/learner content is never executable.

## Storage and recovery

The project document is canonical. A profile registry tracks recent locations independently. Main rejects symlinked metadata, unsupported schemas, changed roots, oversize documents, and detected external edits. Failed replacement leaves previous bytes intact. Corrupt/unknown state is preserved; never silently initialize over it. Save-conflict recovery under [ADR-0012](ADRs/ADR-0012-generation-recovery-and-navigation.md) requires explicit confirmation, fresh validated state, and matching portable identity. Opening, preference/brief writes, generation preparation, and relinking all verify known portable identity. Missing metadata for an already initialized project is a recovery state, never permission to initialize a replacement.

Core serializes metadata operations and attributes results to their project. Renderer holds unsaved drafts by project handle. A result for another project cannot replace the active workspace. Registry failure after a project save is reported separately and does not falsely label the project save as failed.

There is no database or cloud sync. Under [ADR-0014](ADRs/ADR-0014-durable-account-connection.md), account credentials persist in `<userData>/connection/chatgpt.json`, with OS encryption when available and an explicitly disclosed unencrypted local-file fallback otherwise. POSIX connection directories are owner-only (`0700`) and files are `0600`; Windows uses its app-data access controls and normally DPAPI. The new versioned file is authoritative; legacy `chatgpt.enc` is migrated, and sign-out clears both formats. A newly available keychain upgrades local storage. Credentials and installation host identity are separate from educational files.

## Account and models

The ChatGPT connection supports browser sign-in, verified identity, separate plan permission, renewal, model discovery, and local sign-out with remote revocation attempted. Public state contains safe profile/model information, never tokens. Failed model queries do not appear as verified empty catalogues. Preserve a usable connection if replacement sign-in fails or is cancelled. Never fall back to ambient API keys.

Persist model preferences per project and validate changes against the ready connected choices. Under [ADR-0016](ADRs/ADR-0016-requested-extra-model-choices.md), append the explicitly requested Sol/Luna choices after successful discovery, preserving catalogue order/names and avoiding duplicates. Both survive refresh/restart without mandatory tests; choices do not assert per-account entitlement. Failed discovery or missing permission cannot create ready choices. Optional tests under [ADR-0015](ADRs/ADR-0015-explicit-model-access-verification.md) establish independent connection-session proof for each model only after bounded completed inference. Refresh retains proof; reconnect, sign-out and restart clear it. Never run inference on discovery, navigation or selection. Failed/cancelled diagnostics preserve choices and the other model's proof. Preserve other missing saved models visibly until deliberate replacement or fresh discovery. Reading saved content does not require account access; the provider authorizes every inference request.

## Generation and future learning

[ADR-0022](ADRs/ADR-0022-shared-pi-streaming-lifecycle.md) adopts global AI ownership and provisional activity under [AI operations](patterns-ai.md). All five producers use the shared coordinator/Pi/panel lifecycle. Transport completion and a provisional preview remain distinct from independently accepted output and backend-confirmed publication. Preview DTOs accept partial display fields independently of accepted-outline parsing and never enter `.edu`. Domain services retain full accepted/unsaved results and staged edits for storage-only retry when a global terminal display is replaced. Topic previews cannot expose an unidentified/other lesson; final locality and publication remain governed by ADR-0019. Diagnostic public evidence cannot substitute for private completed-stream, identity and text proof or become persisted entitlement.

[ADR-0019](ADRs/ADR-0019-topic-edits-and-project-file-access.md) implements topic edits as replacement of one stable lesson, preserving all other outline fields, ordering and learning direction. A matching existing root folder also receives a versioned `.edu/topic.json` mirror and requested staged file changes. Resolve ownership by a stable plan identity, ID/title/numbered-title match or an exclusive source folder; refuse ambiguous/shared/linked folders. If no folder exists, optional topic material can be created only beneath its lesson ID. Pi may browse/read content throughout the project and stage general requested text-file edits; topic write scope remains local.

Publish staged files and outline through individually atomic replacements plus `.edu/file-transaction.json`. The outline digest is the commit marker; load completes recovery after interruption, restoring pre-save files for an uncommitted outline or verifying a committed result. Unknown external versions or corrupt/changed identities are preserved and reported. Retain unsaved file edits privately for storage-only retry. Confirmed outline-conflict recovery localizes the topic onto the latest outline and preserves current unrelated sections/goals; source-file conflicts still cannot be silently overwritten. The limits and independent path checks in ADR-0019 apply. Original material can change only through explicitly requested content edits, extending the earlier read-only baseline below.

Under [ADR-0017](ADRs/ADR-0017-outline-rewrites-with-saved-context.md), every educational request includes the current saved outline JSON (or null), retained through Pi tool turns. Outline rewrites receive separate bounded learner changes and preserve the written/inferred learning brief. Main/core load authoritative context after project-identity and digest validation. Pi interprets topic numbers against the original one-based lesson order and returns a full validated outline. Reuse generation cancellation, atomic saves, unsaved-result retry and conflict recovery. Require a saved outline before rewriting; an outstanding unsaved result must be saved first.

For rewrites, Pi chooses whether additional scoped reads are needed. Retain previously recorded read-source references with explicitly inherited coverage; only successful new reads establish current source verification. New or previously unread references still require a read-tool call. Normal creation/regeneration retains ADR-0011's relevant-material read requirement. Separate manifests and persistent tutoring remain future proposals.

Description-to-outline generation uses a privileged Pi utility adapter under [ADR-0010](ADRs/ADR-0010-bounded-pi-outline-generation.md). Explicit submission, project-owned operations, bounded cancellation, and distinct generated/saved results are implemented. Folder-based understanding uses bounded text/Markdown snapshots and actual-read coverage under [ADR-0011](ADRs/ADR-0011-scoped-material-understanding.md). Preserve inferred scope separately from the learner’s written brief. Unsupported-only folders return a local input request; ambiguous readable material can ask one useful clarification. Pi coding tools do not belong in the educational surface. Rich tutoring and mastery assessment are outside this milestone. See [security patterns](patterns-ipc-security.md) before extending file or AI access.
