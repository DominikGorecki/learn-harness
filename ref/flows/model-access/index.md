# Independent model access checks

Review extra model choices, explicit diagnostic tests, cancellation, verification badges or restart behavior.

[Test implementation](../../../tests/desktop/model-test.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

A temporary profile starting on the dashboard, an initially unopened saved-outline project, and a signed provider fixture with failed, held and completed model-test responses. No real plan allowance is consumed.

## Journey and assertions

1. Connect, verify four model choices and no inference, and reject renderer-supplied diagnostic model/URL payloads.
2. Request a failing Sol check on the dashboard without a project; accepted admission closes account settings and focuses the global dock. Capture the safe failure status, dismiss it and verify dashboard heading focus.
3. Open the project, start a held check, reuse its same-target initial snapshot and reject competing diagnostic/educational starts without extra requests or educational writes. Verify named evidence-region semantics and the nonterminal waiting hint after 30 real seconds without response bytes, with Cancel still enabled. Cancel and verify the model utility has actually exited while choices remain available.
4. Return the initial testing snapshot promptly for Sol and observe boolean-only partial evidence. Visit a saved topic, traverse Back through its overview to the dashboard, then Forward through the overview to the topic without a project-cancellation prompt, preserving the operation identity, request count and project bytes. Keep Cancel available and dismiss/reopen settings without cancelling. Complete a response receiving for more than 30 real seconds. Complete Luna independently; verify the next operation replaces Sol despite restarting its local sequence, separate badges, fixed tool-free requests and correct target identity, then refresh while retaining verification and excluding secrets from public state.
5. Capture verified Light and Dark panels; the Dark checkpoint renders the same account state with the Dark theme attribute.
6. Save Sol as project preference, restart and verify both extra options/preference remain while session verification resets.

## Run and refresh

```powershell
npm run test:desktop -- tests/desktop/model-test.spec.ts --grep "@model-access( |$)"
```

The flow ID is also a test tag (`@model-access`); use `--grep "@model-access( |$)"` to select it exactly when names overlap. Passing runs replace only this flow's platform set and regenerate the table below. Failed/skipped/interrupted runs keep the previous references; inspect their age before relying on them. See the [maintenance workflow](../../patterns-flow.md#creating-or-changing-a-flow).

## Evidence limits

Verification comes from a local protocol fixture. The Dark checkpoint changes the renderer theme attribute directly to inspect styling; the appearance flow separately tests the user-facing settings behavior.

Captures show Electron renderer content, without native title bars/menus. Any visible temporary absolute project paths are masked. Fixture account labels and learning text are synthetic. Visual references supplement the assertions and do not establish learning mastery or live-account access.
