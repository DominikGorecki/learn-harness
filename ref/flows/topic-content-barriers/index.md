# Chapter dispatch and cleanup barriers

Review durable dispatch, accounting and cleanup barriers for chapter image requests through the shared AI coordinator and typed Electron bridge.

[Test implementation](../../../tests/desktop/topic-content.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

An isolated development Electron profile, a saved topic and deterministic text/image HTTP fixtures. Test-owned filesystem failures and held genuine worker exit events expose actual barrier ordering; no paid live request is used.

## Journey and assertions

Actual filesystem faults on durable intent and requested checkpoint prevent image HTTP. A terminal-write failure occurs after one image request and denies asset acceptance. Restart preserves the intent and partial immutable transition as corrupt accounting state: the latest outcome is unknown, the safe error is STORAGE and further paid dispatch is blocked.

Global typed Sol/Luna admission remains BUSY in both orderings of actual worker exit and pending durable writes. The write-first case independently reads durable known cost before checking BUSY while genuine exit delivery remains held. Cancellation preserves known billing and awaits cleanup. Held storage-only Retry Save also returns global BUSY to competing inference, creates no new AI activity and makes no provider request.
