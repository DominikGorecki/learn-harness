# Explicit image metadata preflight

Review explicit chapter image activation with a persisted ordinary key and missing, aged or previously failed metadata, through the real Electron bridge.

[Test implementation](../../../tests/desktop/topic-content.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

Isolated application profiles, saved topics and deterministic loopback text/image fixtures. Cached metadata and provider prices are synthetic; no live key or paid provider request is used.

## Journey and assertions

Startup, saved reading and cached quotes issue no OpenRouter HTTP requests. Explicit illustrated generation refreshes missing or aged metadata before dispatch, and recovers a previous failed refresh. A fresh compatible cache needs no discovery request. Missing keys and deliberate text-only generation make no discovery request. Failed discovery publishes valid prose as needs-images without an image POST; Complete images reports unavailable and performs no text request.

A held discovery request owns the current provider key/model and shared AI admission. Cancellation retains ownership until that bounded request drains, then releases it without any text or image inference. Unit evidence additionally pins previously displayed settings across changed metadata and rejects settings that are no longer supported.

## Evidence limits

This is a nonvisual bridge/process/storage journey. It does not qualify live model availability/prices, educational quality, visual composition, accessibility, other platforms or packaged startup.
