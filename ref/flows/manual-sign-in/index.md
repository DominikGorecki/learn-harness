# Manual sign-in link

Review browser-opening failure, copied-link recovery or sign-in clipboard behavior.

[Test implementation](../../../tests/desktop/account.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

A temporary profile and signed local provider. The test makes shell.openExternal fail, and uses a synthetic clipboard sentinel; it clears the copied fixture link after following it.

## Journey and assertions

1. Start sign-in and verify the browser-opening recovery message.
2. Copy the sign-in link and verify the clipboard origin, PKCE method and state without publishing their values.
3. Confirm the public snapshot omits PKCE data; capture the copied-link recovery panel.
4. Follow the clipboard URL through the fixture callback and verify connected state and removal of the copy-link action.

## Evidence limits

This establishes local clipboard/callback behavior. It does not automate a real authentication dialog or verify WSL/browser routing.

Captures show Electron renderer content, without native title bars/menus. Any visible temporary absolute project paths are masked. Fixture account labels and learning text are synthetic. Visual references supplement the assertions and do not establish learning mastery or live-account access.
