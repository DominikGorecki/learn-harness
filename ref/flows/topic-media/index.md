# Authorized local chapter media

Review actual Chromium requests to the narrow local raster scheme and named chapter capability authorization.

[Test implementation](../../../tests/desktop/topic-content.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

An isolated development Electron session, an owned saved chapter and deterministic local raster assets. The renderer retains sandboxing, context isolation and its restrictive CSP.

## Journey and assertions

With both accounts disconnected, named capabilities read saved prose and return safe provider state. An actual Chromium image GET succeeds for the current opaque chapter identity in the owning trusted window. Encoded aliases, extra query fields, unknown candidates, a main-process network GET, POST and another window are denied. A valid PNG data URL is denied by the restrictive image CSP.

The second window's preload invokes all sixteen implemented chapter/provider capabilities and receives FORBIDDEN. Serving requires owning-window/main-frame authorization plus independent canonical manifest/asset resolution; public identity alone grants no access.

## Run and refresh

```powershell
npm run test:desktop -- tests/desktop/topic-content.spec.ts --grep "@topic-media( |$)"
```

Passing runs refresh only this flow through the configured reporter. Failed/skipped/interrupted runs retain previous evidence. See the [maintenance workflow](../../patterns-flow.md#creating-or-changing-a-flow).

## Evidence limits

This is a nonvisual security/bridge journey. Real Chromium/utility assertions are distinct from renderer visual acceptance, live generated-image quality, screen-reader/native OS behavior and hardened packaged startup.
