# Buffered image utility transport

Review the sanctioned fixed-image utility profile, correlated private acknowledgements, buffered response liveness and actual raster decoding.

[Test implementation](../../../tests/desktop/image-worker.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

An isolated development Electron host, a restricted utility environment and a local HTTP image fixture with synthetic credentials and generated raster bytes. No live account or paid request is used.

## Journey and assertions

1. Bundle a test-only main harness beside the real utility entry, then launch an isolated development host. The harness uses the actual worker lifecycle, provider service and ledger; it is removed before packaging.
2. Generate one fixture raster through the fixed image route and acknowledgements. Compare accepted bytes and digest, exact request/model/provider settings, reported cost and checkpoint disposition.
3. Fail intent, requested-checkpoint and terminal writes separately. Assert zero paid HTTP requests for the first two, exactly one for terminal failure, no accepted file and retained unresolved intents where applicable.
4. Hold terminal persistence, cancel and observe the actual utility exit. Provider admission remains BUSY until the held write finishes; its reported cost survives without accepting pixels.
5. Hold delivery of a genuine exit event after accounting and accepted-byte checkpointing. Assert the PID is absent while provider admission remains BUSY until exit observation is released.
6. Send headers immediately, delay initial body bytes beyond 180 seconds, then receive chunks without exceeding byte-idle limits for more than 180 further seconds. Verify waiting feedback, independent health, one request and exact accepted bytes.
7. Close the host/server and remove the test-only harness and temporary profile/files.

The accepted Windows run measured 216,164 ms before initial bytes and 210,033 ms of receiving, with 85 health frames, one image request and 96 accepted raster bytes. The initial fixture run completed the image but measured only 175 seconds of receiving; its threshold failed, so the fixture interval was corrected to 30 seconds and rerun. Successful-run metadata below belongs to the corrected passing run.

## Run and refresh

```powershell
npm run test:desktop -- tests/desktop/image-worker.spec.ts --grep "@image-worker( |$)"
```

Passing runs refresh this flow's platform manifest through the configured reporter. Failed/skipped/interrupted runs retain previous evidence. See the [maintenance workflow](../../patterns-flow.md#creating-or-changing-a-flow).

## Evidence limits

This is a nonvisual utility transport journey. No screenshots are generated. Direct utility tests do not establish typed renderer bridge authorization, durable chapter publication, global coordinator admission, live provider billing or packaged/native startup. Those require their own integration and qualification evidence. Deterministic unit tests separately cover adversarial private frames and controlled timer/write/exit races.
