# Packaged Pi worker

Review ASAR worker startup, runtime dependency packaging, scoped material access, chapter guidance and native image decoding.

[Test implementation](../../../tests/desktop/packaged-worker.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

An existing current-OS packaged ASAR, owned sample notes and the local provider fixture. The test is skipped in normal desktop runs and enabled by npm run test:packaged after packaging.

## Journey and assertions

1. Launch a development Electron host without changing packaged security fuses.
2. Fork the Pi utility entry from the packaged ASAR with the sanctioned outline profile, restricted environment, sample project and fixture request. Verify scoped source coverage and exactly three outline tool requests.
3. Sequentially run both fixed tool-free Sol/Luna model-access profiles from the same ASAR entry and dependencies. Check actual returned identity, completed status, nonempty final text evidence and clean EOF; each diagnostic adds exactly one request with no project material or tools.
4. Run the fixed-image profile from the same packaged entry. Persist private intent and terminal evidence before their acknowledgements; decode through packaged Sharp, persist the accepted raster and acknowledge it before completion. Compare exact bytes/digest, known cost, one request and absence of credentials/prompts in the asset frame.
5. Run a text-only chapter profile from that ASAR entry. Persist each private submission before acknowledging it; verify five text requests, a complete chapter result and bundled educational-image guidance plus `generate_topic_image`, without project-writing tools.
6. Await each worker's actual exit and pending private writes before accepting its result, check zero exit code and absent PID, and verify only the sanctioned environment keys were forwarded.
7. Clean up the owned host, worker, providers and temporary project.


The flow ID is also a test tag (`@packaged-worker`); use `--grep "@packaged-worker( |$)"` to select it exactly when names overlap. For the packaged-worker flow use `npm run package` then `npm run test:packaged` instead. Passing runs replace only this flow's platform set and regenerate the table below. Failed/skipped/interrupted runs keep the previous references; inspect their age before relying on them. See the [maintenance workflow](../../patterns-flow.md#creating-or-changing-a-flow).

## Evidence limits

This verifies packaged worker code/dependencies and native raster decoding under a development host. Its direct port harness does not compose the production lifecycle, call ledger or global coordinator; the separate image-worker and chapter integration flows own those checks. It does not prove hardened packaged-window startup, another platform/architecture, installer acceptance or live inference. No screenshots are generated.

Captures show Electron renderer content, without native title bars/menus. Any visible temporary absolute project paths are masked. Fixture account labels and learning text are synthetic. Visual references supplement the assertions and do not establish learning mastery or live-account access.
