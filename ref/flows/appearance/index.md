# Appearance and local preference

Review Light/Dark styling, settings, draft preservation, keyboard focus or local preference persistence.

[Test implementation](../../../tests/desktop/appearance.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

An empty temporary project named Learning about oceans, a fresh app profile and a sample ocean-current learning draft. No provider fixture or inference is needed.

## Journey and assertions

1. Open the sample folder and enter the learning draft.
2. Select Light, capture Settings and the workspace; use radio keyboard navigation to select Dark and capture both views again.
3. Dismiss Settings and verify trigger focus, unchanged draft, Dark surface colors, unchanged project files and no AI activity/panel from appearance changes; capture the disconnected account panel.
4. Resize content to 600 × 640 and set 200% zoom; verify mode controls remain visible without horizontal overflow.
5. Restart, verify the saved mode, switch to Light and reload; then block preference storage and verify a session-only Dark choice with explanatory feedback.

## Run and refresh

```powershell
npm run test:desktop -- tests/desktop/appearance.spec.ts --grep "@appearance( |$)"
```

The flow ID is also a test tag (`@appearance`); use `--grep "@appearance( |$)"` to select it exactly when names overlap. See the [maintenance workflow](../../patterns-flow.md#creating-or-changing-a-flow).

## Evidence limits

The assertions establish renderer preference and interaction behavior. Captures cover normal-size settings, composer and account surfaces; narrow settings and blocked-storage feedback are tested but not pictured.

Captures show Electron renderer content, without native title bars/menus. Any visible temporary absolute project paths are masked. Fixture account labels and learning text are synthetic. Visual references supplement the assertions and do not establish learning mastery or live-account access.
