# Appearance and local preference

Review Light/Dark styling, settings, draft preservation, keyboard focus or local preference persistence.

[Test implementation](../../../tests/desktop/appearance.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

An empty temporary project named Learning about oceans, a fresh app profile and a sample ocean-current learning draft. No provider fixture or inference is needed.

## Journey and assertions

1. Open the sample folder and enter the learning draft.
2. Select Light, capture Settings and the workspace; use radio keyboard navigation to select Dark and capture both views again. In each theme, verify the existing Learning Studio projects control retains its exact text/name, decorative 22px currentColor glyph and three page paths.
3. Dismiss Settings and verify trigger focus, unchanged draft, Dark surface colors, unchanged project files and no AI activity/panel from appearance changes. Measure central composer text/action/focus contrast against both opaque gradient endpoints in each theme. Disable its background image and verify the filled fallback, intact draft and keyboard-reachable Create outline command, then restore it and capture the disconnected account panel.
4. Resize content to 600 × 640 and set 200% zoom; verify mode controls remain visible without horizontal overflow and capture both themes with reduced motion. Each zoom capture waits for the selected radio, HTML theme and computed dialog color, then verifies actual dialog background pixels and publishes that exact native frame; Light and Dark bitmaps must differ.
5. Restart, verify the saved mode, switch to Light and reload; then block preference storage and verify a session-only Dark choice with explanatory feedback.

## Evidence limits

Reviewed Light/Dark composer captures show the shared editorial workspace foundation and quiet action treatment; the settings/account panels and sidebar retain their existing composition. Gradient endpoint measurements establish minimum label/action/focus contrast for this composer. The filled fallback is exercised in Dark without a separate capture. They are focused evidence, not a full audit of every state, hover treatment or future overview/topic surface.

The existing brand slot now shows the selected Sculpted aperture with theme-aware accent color; Learning Studio text, sidebar layout and functional icons retain their composition. Actual-size glyph/native export review and the documented antialiased small-edge qualification live with the [branding assets](../../../assets/branding/README.md). Renderer captures do not establish executable resources or native taskbar/Dock/launcher presentation.

The assertions establish renderer preference and interaction behavior. Captures cover normal-size settings, composer and account surfaces, and sectioned Appearance controls at narrow size/200% zoom in both themes. Blocked-storage feedback is tested but not pictured. Settings initially opens on OpenRouter; this journey explicitly selects Appearance and preserves the modal's radio, Escape and trigger-focus behavior.

Captures show Electron renderer content, without native title bars/menus. Any visible temporary absolute project paths are masked. Fixture account labels and learning text are synthetic. Visual references supplement the assertions and do not establish learning mastery or live-account access.
