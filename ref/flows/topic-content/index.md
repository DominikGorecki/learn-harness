# Checkpointed topic chapter generation

Review explicit chapter generation, shared AI admission, durable progress and inference-free publication recovery through the typed Electron bridge.

[Test implementation](../../../tests/desktop/topic-content.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

An isolated development Electron profile, a saved project/topic, owned learning sources and deterministic text/image HTTP fixtures. Accounts, pricing and learning content are synthetic; no paid live request is used.

## Journey and assertions

The journey generates a two-section chapter through seven text requests and two distinct decoded image requests. It checks saved-objective coverage, the digest of actual source bytes including a UTF-8 BOM, and unchanged project metadata, source and unrelated-topic bytes. A reopened isolated profile reads the published chapter without inference. Startup and cached image quotes make no provider HTTP request.

While genuine chapter worker exit delivery is held, typed Sol admission and OpenRouter key removal return BUSY. After actual exit observation, the worker PID is absent and admission releases. The separate recovery and barrier flows cover explicit text-only completion, uncertain-call retry and durable-write failure ordering.

## Run and refresh

```powershell
npm run test:desktop -- tests/desktop/topic-content.spec.ts --grep "@topic-content( |$)"
```

Passing runs refresh only this flow through the configured reporter. Failed/skipped/interrupted runs retain previous evidence. See the [maintenance workflow](../../patterns-flow.md#creating-or-changing-a-flow).

## Evidence limits

This is a nonvisual backend/bridge integration journey. It does not establish the chapter-reader/Settings layout, live provider eligibility/billing, pedagogical quality, screen-reader behavior, another OS or hardened packaged startup. Those require their separate evidence.
