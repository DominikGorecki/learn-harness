# Long outlines and unavailable state

Review offline outlines, long content, narrow/zoomed layout, read-only projects or missing/corrupt metadata.

[Test implementation](../../../tests/desktop/reading.spec.ts) · [Flow patterns](../../patterns-flow.md)

## Starting conditions

A temporary offline project with 40 long topics, a missing account, a saved model and a deliberately corrupt second project. No inference provider is needed.

## Journey and assertions

1. Open Dark mode, load the long saved outline offline and expand a topic by keyboard.
2. Resize to 600 × 640 at 200% zoom; verify overflow, working-area height and reachability/32px targets for the independent Open first topic and Edit outline commands, then capture with Electron native capture.
3. Verify reduced motion and preserved reading position when changing appearance. Confirm offline reading/appearance creates no AI operation/panel and leaves saved outline bytes intact; on eligible non-Windows/non-root hosts, remove write permissions and verify readable content plus disabled saving.
4. Remove only the owned metadata temporarily; verify recovery without silent initialization, restore it and retry.
5. Open corrupt metadata, retry, verify its original bytes remain and capture the recovery screen with the local path masked.

## Evidence limits

The zoomed checkpoint records one scrolled viewport, including the independent overview commands. Reading the full long outline requires scrolling; the image does not include all modules.

Permission behavior is conditional by platform/user. Captures cover zoomed reading and corrupt-state recovery; they do not certify accessibility or Windows read-only filesystem semantics.

Captures show Electron renderer content, without native title bars/menus. Any visible temporary absolute project paths are masked. Fixture account labels and learning text are synthetic. Visual references supplement the assertions and do not establish learning mastery or live-account access.
