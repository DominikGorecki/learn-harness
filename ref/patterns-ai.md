## Ownership and producer recipe

1. Define a sanctioned task profile and domain acceptance adapter: operation kind, authorized model resolution, project/topic or account owner, permitted data/tools and safe preview policy. This does not authorize automatic/background AI or arbitrary tools.
2. Claim the main-composed `AiCoordinator` synchronously before any authorization or preparation can yield. `claim` returns a private lease and `reused`; launch work only when `reused` is false. Competing requests fail BUSY, without a queue/provider call. Same fixed diagnostic target reuses its lease. Main must permit credential renewal for that owner while denying competing inference/account replacement.
3. Register `lease.setCancellation` before yielding. Its callback must await actual task/worker cleanup and must never await `lease.settled`, avoiding a self-wait. Use the lease signal for immediate abort. Cleanup failure keeps ownership until explicit failed/cancelled owner settlement; aborted owners cannot publish late phase/preview/success updates.
4. Execute through the shared Pi utility adapter with sanctioned endpoints, token on the private port, restricted environment, request whitelist, no redirects/provider storage/automatic retries and unchanged request/response/turn/file budgets. No new direct provider fetch bypass or separate progress-only modal without a new durable decision.
5. Publish actual bounded progress and use the workbench panel. Bind operation/project/stable-topic identity from the trusted launch context; provider turn and candidate revision order updates. Replace repair candidates instead of appending duplicate outlines. `phase` is immediate; `progress` coalesces latest state at 100 ms. `AiActivitySnapshot.revision` increases globally throughout the app session and orders initial queries, events and changes of owner. `AiOperation.sequence` starts at zero for each `operationId`; compare it only within that same operation. A new owner with a smaller local sequence must not be rejected as stale. A newer turn can begin a new candidate-revision sequence; older pairs are rejected.
6. Keep domain ownership through validation/publication. Call `phase('saving')` before publication; Cancel then fails BUSY. Settle saved only after backend-confirmed storage, verified only after independent diagnostic proof. Other terminal outcomes release admission exactly once. Full accepted/unsaved output and staged files remain in the domain service for storage-only retry, independently of the global panel.
7. Add focused race/bounds/privacy tests, actual Electron bridge/process tests and reviewed flow captures. Retain separate live-account/platform/accessibility gates. See [development/testing](patterns-development-testing.md) and [flow maintenance](patterns-flow.md).

## Transport acceptance and liveness

### Adopted chapter/media extension

[ADR-0026](ADRs/ADR-0026-illustrated-topic-content-and-openrouter-media.md) adds `generate-topic-content` and `regenerate-topic-image` contracts. The chapter runtime and fixed-image utility are implemented; standalone replacement integration remains pending. Initial chapter IDs are allocated before claim; continuation includes the known chapter/run identity before asynchronous main resolution. Chapter image calls are children of its lease. Replacement uses the selected fixed image model and its own lease, with no ChatGPT call. New `chapter`/`image` previews require selected topic/chapter identity (and selected image for replacement), contain no prompt/URL/binary data, and retain all existing batching/frame caps. `writing`/`generating-images` phases express actual work; `paused`, `incomplete` and `candidate` distinguish checkpoint release, published needs-images prose and an unaccepted replacement. An incomplete publication settles only from Saving; pause/candidate cannot settle from Saving. Domain acceptance still establishes the actual result.

Chapter activations have 48 text turns, 24 sections and six planned image slots; checkpoints separate activation/lifetime counters and retain call IDs/unresolved image states. Continue never silently replays an unknown paid dispatch. Media uses 300-second initial wait, then 60-second received-byte inactivity, independent worker health, accepted EOF and 32 MiB response bound. Decode/transfer up to 16 MiB raster assets off main through private channels; never put them in public activity frames. The app-owned Pi-compatible dedicated OpenRouter image adapter is an explicit scoped transport extension; the existing ChatGPT text transport is unchanged. Every dispatch requires main's durable intent acknowledgement; no retry/fallback/startup inference. Metadata refresh is non-inference, bounded and audited.

The `chapter` profile supplies app-owned versioned educational-image guidance, scoped read-only source tools, validated plan/section/summary submissions and `generate_topic_image`. Main independently accepts objective coverage, actual raw-byte source reads and each fixed image request. Every checkpoint, intent, billing and asset acknowledgement is awaited; actual utility exit and pending durable writes precede admission release. Continuation uses the checkpoint's recorded text model. Completing accepted prose needs no new ChatGPT authorization.

Explicit image activation claims provider ownership before refreshing missing, aged or previously failed metadata. Retain previously displayed compatible settings across discovery; changed defaults cannot silently increase output settings. Failed discovery dispatches no image request: initial generation may publish needs-images prose, while Complete images reports unavailable. Startup, reading, cached quotes and deliberate text-only generation issue no metadata HTTP. Cancellation holds admission and provider configuration until the bounded metadata request drains, then performs no inference. See the [preflight flow](flows/topic-content-preflight/index.md).

Chapter Retry Save and Discard use the coordinator's narrow `reservePublication`: synchronous exclusion, no inference or new workbench activity, and shutdown waits for the reservation to drain. Retry Save uses the exact retained validated result, never calls a model, and leaves conflicts preserved. This does not change outline storage recovery.

Use 180-second received-byte inactivity rather than total duration. Arm at request start, reset once on entry into body wait and on every nonempty body chunk before event parsing. SSE comments/fragments count; an open silent socket, empty chunk, local heartbeat or UI activity does not. Each provider turn has a fresh interval; local tools disarm network waiting. Show a nonterminal waiting hint after 30 seconds without bytes, with Cancel available. Worker spawn/health deadlines remain independent (30-second spawn, 5-second heartbeat/30-second health silence).

Require Pi acceptance plus private protocol completion and clean body EOF for the same request before successful terminal/tool delivery. Continue inactivity through the response tail, including after `[DONE]`; errors, malformed tails, transport failure, post-completion silence or cancellation reject acceptance. Bound private observation without retaining reply content; count body bytes once before branching and cancel all readers together. No second inference request or raw public protocol events.

## Provisional public state

Shared [activity contracts](../src/shared/ai/activity.ts) define only serializable display data; they are separate from `LearningOutline`/`SavedOutline`. Incomplete outline fields are allowed. Topic lesson content requires the selected stable lesson ID; absent identity shows waiting without another lesson. Diagnostic previews contain only boolean reply/completion/model-match evidence; completed-looking evidence still requires private domain verification.

Preview prose is limited to 64 KiB UTF-8, history to 40 entries and labels to 256 characters. The 96 KiB complete-frame cap includes escaping and metadata; abbreviation and cumulative omitted history are explicit. Activity entries reflect actual operations; `upcoming` may mark planned validation/save, while completed reads require successful actual reads. No raw tool arguments/results, private thinking, read-file content, file baselines, tokens or provider errors belong in public frames or logs.

Start/phase/terminal state bypasses preview coalescing. Subscribers run asynchronously outside producer callbacks; exceptions and unresolved subscriber promises cannot alter domain results. Cancel/settlement clears pending preview delivery, rejects old ownership and preserves the terminal presentation without owning admission. Snapshots are immutable copies; activity remains memory-only. Dismiss hides a terminal panel in renderer presentation state; it does not call a main dismissal capability or clear the coordinator. The coordinator retains one bounded latest settled snapshot until another lease replaces it or the app exits. That snapshot owns no admission, accepted result or persisted transcript.

## Current inference and timeout inventory

| Start / owner | Execution / acceptance |
| --- | --- |
| Create outline, rewrite outline, rewrite topic — core `GenerationService` | Synchronous shared lease; main-owned account/project authorization; `outline` Pi utility profile; independent outline/source/topic acceptance and recoverable publication. |
| Fixed Sol and Luna tests — main `AccountService` | Synchronous shared lease and same-target reuse; main-owned owner-aware credential preparation; fixed tool-free `model-access` Pi utility profile; private completed identity/text proof and actual worker exit before session verification. |
| Generate/continue chapter, complete illustrations, explicitly retry a chapter image — core `TopicContentService` | Synchronous shared lease; main-owned saved-topic/source/provider authority; `chapter` Pi profile and fixed `image` children; independent checkpoints/publication and actual-exit plus durable-write cleanup. |

Main composes one coordinator in [main/index.ts](../src/main/index.ts). Both [outline execution](../src/main/generation/pi-outline-engine.ts) and the [fixed diagnostic profile](../src/main/generation/pi-model-access-profile.ts) use [streamPiTurn](../src/main/generation/pi-transport.ts), the production ChatGPT text inference fetch boundary. The sanctioned [OpenRouter image profile](../src/main/generation/pi-image-profile.ts) uses Pi's image interface with main-approved fixed-route authority; it does not change text inference. The [main model-test adapter](../src/main/auth/model-access-test.ts) verifies private proof and performs no provider fetch. Renderer starts share the typed [activity hook](../src/renderer/src/features/ai/useAiActivity.ts); no renderer transport or caller-selected generic inference profile is exposed.

The [byte liveness timer](../src/main/generation/pi-stream-liveness.ts) owns 180-second inactivity, a 30-second hint and bounded reporting; [worker lifecycle](../src/main/generation/worker-lifecycle.ts) owns spawn/health and a five-second cooperative-stop grace before kill, always awaiting actual exit. The outline engine's internal `timeoutMs` option is passed as `idleMs`; it is not a hidden total deadline. SDK request setup cannot impose a buffered-body deadline on receiving streams; retain the pinned-adapter regression and real elapsed test. OAuth/JWKS, renewal, discovery, revocation, login-loopback and static app-asset requests retain their separate non-inference timers and are deliberately excluded from this inventory.
