# IPC and security patterns

Governed by [ADR-0002](ADRs/ADR-0002-sandboxed-capability-ipc.md) and [ADR-0008](ADRs/ADR-0008-chatgpt-plan-connection-and-pi-foundation.md).

## Capability contract

Under [ADR-0022](ADRs/ADR-0022-shared-pi-streaming-lifecycle.md), named `getAiActivity`, `onAiActivityChanged` (with event stripping/unsubscribe) and strict `cancelAiOperation({ operationId })` capabilities are implemented through the same owning-window/frame/origin/entry authorization. Shared runtime parsers and the coordinator bound immutable provisional frames to 96 KiB serialized, preview text to 64 KiB UTF-8 and history to 40 entries/256-character labels. Topic previews require the selected stable lesson ID; diagnostic previews contain evidence booleans only. No tokens/raw provider or tool data, authoritative result, generic task or caller-controlled timeout/path/model capability is added. See [AI operations](patterns-ai.md) for foundation status and pending transport/producer/UI migration; the diagnostic adapter below remains the legacy runtime until migration.

Shared contracts define named account, workspace, and outline capabilities on `window.learning`. Folder selection happens in main; callers identify previously opened projects and owned runs. Do not expose raw `ipcRenderer`, arbitrary channel names, filesystem paths, subprocess APIs, environment variables, or credentials.

`src/shared/account.ts` adds named account get/connect/cancel/reopen/copy-sign-in-link/models/disconnect capabilities and `onAccountChanged`. The subscription strips Electron event objects and returns an unsubscribe function. Account mutations accept no caller-supplied URLs or credentials; even unexpected payloads to no-input actions are rejected. The copy action writes only the active internally constructed authorization URL to the OS clipboard in main; it exposes neither the URL in snapshots nor general clipboard access. Main sends sanitized snapshots only to the owning window.

Requests/results are structured-clone-compatible DTOs. Public replies use `ApiResult<T>` with bounded error codes and safe messages. Expected application errors retain their code; unexpected failures return a generic INTERNAL message without serialized stack traces or sensitive logs.

## Authorization and runtime validation

Each main handler verifies the live owning window, exact sender webContents, the main frame, its effective origin, and its app-entry URL. A trusted origin alone does not authorize a sibling frame or another window. Production trusts `learningapp://workspace`; development trusts only `http://127.0.0.1:5173`. Mutation payloads arrive as `unknown` and pass strict field/type/length parsers before core sees them. Project/run/model membership is checked by core and account services. TypeScript types do not validate incoming values.

## Renderer restrictions

Keep `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`, and `webviewTag: false`. Deny renderer navigation, redirects, popups, embedded webviews, and browser permissions in the app's dedicated `persist:edu-harness` session. Under [ADR-0013](ADRs/ADR-0013-chatgpt-inspired-appearance.md), this persistent UI partition retains the non-sensitive renderer appearance preference; it does not grant browser permissions or change credential storage. The account service may open its internally constructed, origin/path-allowlisted authorization URL in the system browser. No generic external-link capability is exposed.

Built HTML/assets are served through a registered secure standard custom protocol. The handler allows GET requests only and a small fixed asset-path shape under the built renderer directory. It does not turn renderer-provided paths into general filesystem access. Production CSP disallows inline scripts/styles, network connections, frames, objects, and form submission. Dev CSP permits Vite refresh scripts/styles and its exact loopback websocket. Packaged apps ignore the development renderer URL.

## Explicit model diagnostic

[ADR-0015](ADRs/ADR-0015-explicit-model-access-verification.md) adds named no-input test/cancel capabilities, authorized through the existing account handlers. Main chooses the fixed Sol slug, destination and short prompt; callers cannot supply models, URLs, tools or material. The account adapter owns a 30-second, 256-KiB HTTP/SSE request with no redirects and safe error mapping. Only completed inference with matching model identity and nonempty assistant text, observed in streamed output-text deltas or final message content, creates session proof. Deltas alone never verify access; retain only a boolean for streamed text evidence. Never expose credentials or raw diagnostic response text. Serialize the test with account replacement and outline authorization, and abort it on cancellation or app disposal.

[ADR-0016](ADRs/ADR-0016-requested-extra-model-choices.md) adds the named no-input Luna test with the same fixed-target policy. Independent per-model proof appears only as safe IDs in account snapshots. Deduplicate the same active target; reject a competing target as busy. Fixed Sol/Luna picker additions are explicitly requested choices, not entitlement proof; normal connected credentials, membership checks, public destination and provider recovery still govern each outline request.

Each explicit test prints one main-console summary of numeric transport/timing counters, fixed outcome categories and allowlisted protocol/model values. Under [ADR-0018](ADRs/ADR-0018-development-file-diagnostics.md), unpackaged runs also persist this safe summary as a `model.test` JSONL event. Replace arbitrary provider strings with `unrecognized`; never include account identity, token/header values, prompts, output text or raw errors. Specific safe failure messages distinguish HTTP/stream rejection, missing completion, incomplete response, model mismatch and missing output. Diagnostics do not grant access, persist entitlement or change verification criteria.

## Development diagnostic boundary

Main alone writes local diagnostics using strict safe scalar projection. Never log payloads, whole snapshots, paths, URLs, credentials, identity, material or arbitrary messages/stacks. Arbitrary console output records level, argument/character counts and safe error type/app bundle line/column only. Use fixed structured events and counters for details. The internal `diagnostics:renderer-failure` channel accepts only error/rejection metadata, requires the same live owning window/main frame/exact origin/entry authorization as capabilities, and is rate limited. It is not exposed through `window.learning`. Worker diagnostics retain the private port and safe projection at sender and collector. Logging failures cannot alter application behavior. See ADR-0018 for retention and fatal-exit limits.

## Private connection files

[ADR-0014](ADRs/ADR-0014-durable-account-connection.md) keeps login persistence in main's application-profile adapter. Store encrypted payloads when OS protection is available; otherwise use a disclosed local credential file with owner-only POSIX permissions. This is a persistent fallback, not a claim of keychain encryption. Reject symlinked directories/files, bound reads and validate stored formats. Do not copy credentials into renderer state, UI preference storage, project metadata or logs. Preserve undecryptable state; encryption failures do not trigger automatic plaintext downgrade.

## Adding capabilities

Extend shared DTOs, runtime validation, and API types first; add one preload wrapper and one authorized main handler; cover the rejected inputs and real IPC journey. Keep renderer text as React text. Before adding Markdown/HTML, imports, external navigation, or model-produced actions, define their trust boundary explicitly. All event subscriptions must strip Electron event objects and return unsubscribe functions.

## Generation boundary

[ADR-0019](ADRs/ADR-0019-topic-edits-and-project-file-access.md) extends the read-only Pi rule below with project-wide browse/read and staged UTF-8 content creation/editing. The named `rewriteTopic` capability validates a stable saved lesson ID and bounded changes. Load authoritative scope in main/core; callers cannot provide JSON, paths or write permissions. A topic request may read the whole project but may write only inside its resolved topic folder. Independently merge only its stable lesson at each acceptance boundary, preserving all other outline fields and lessons. Revalidate paths, links/junctions, folder identity, file baselines and sharing in main. Reject arbitrary/external paths and Pi writes to root project metadata, the recovery journal or Git internals. No shell, code execution or deletion tool is granted. Project file contents remain untrusted data, even when they resemble agent instructions. Credentials stay outside projects.

[ADR-0017](ADRs/ADR-0017-outline-rewrites-with-saved-context.md) adds `rewriteOutline` with strict project/model identifiers and nonblank changes up to 32,000 characters. Renderer callers cannot supply outline JSON, source evidence or filesystem paths. Core/main obtain validated saved context and pass it privately to the existing Pi worker on all educational requests. For rewrites only, recorded read-source evidence may carry forward with explicit provenance; new references require actual scoped reads. Outline JSON and change text remain untrusted learning data. No source-writing or arbitrary discovery tool is added.

[ADR-0010](ADRs/ADR-0010-bounded-pi-outline-generation.md) governs the Pi worker. Tokens travel on the private main/utility port and never enter public snapshots. Only educational tools are registered. The plan request whitelist excludes unsupported fields and arbitrary endpoints. Require successful completed streams and independent outline validation before persistence. [ADR-0011](ADRs/ADR-0011-scoped-material-understanding.md) permits bounded read-only material snapshots after explicit submission. Pi lists permitted files and reads exact snapshot keys; it cannot follow symlinks, load project agent instructions, execute code, or write source files. Every new cited path must appear in actual read-tool evidence; ADR-0017 permits explicitly inherited read evidence for retained references during a rewrite. Source/model text is rendered as text, never executable markup or code.
